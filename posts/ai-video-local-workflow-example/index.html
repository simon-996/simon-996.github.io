零基础学AI视频（四）：从项目素材到本地生成，一个镜头怎么做？

上一篇我们认识了 ComfyUI 和 Pika H3 Flex 的本地参考图生成视频流程：上传图片、输入文字，尝试生成一条视频。

如果我已经有了人物图片和场景图片，希望视频中的人物、环境和构图都参考这些素材，又该怎么办？

这篇文章结合我的《全球学历含金量下降100倍》项目，拆解其中的一个镜头。我们先看懂准备什么、素材怎么对应、工作流做什么，以及生成后要检查什么。

这篇展示的是项目中的单镜工作流及素材组织方法。项目工作流和素材目前没有随博客提供下载；读者可以用自己的图片，按照同样思路练习。文中所述版本已做静态核对，尚未在目标 ComfyUI 环境完成该版本的视频生成验证，实际画面、声音和节点兼容性仍需检查。

一、这次想做一个什么镜头？

项目的开场是一位新闻主播坐在演播室里，向观众播报一条消息。这里选用的是 01A 镜：

女主播正对镜头坐在演播桌后，双手自然放在桌面，以严肃、专业的语气说：“全球学历含金量下降100倍。”

拍摄要求是正面、平视、中景、固定机位：主播的脸、双手和桌子的边缘都要看得见。

如果只把这句话交给模型，主播和演播室的样子仍由模型自行生成。为了让画面更接近项目设计，我为这个镜头准备了三张参考图。

二、准备三种参考图

顺序 项目里的素材 这张图用来参考什么
Picture 1 主播角色图 主播的脸、头发、眼镜和服装
Picture 2 新闻演播室图 演播室环境、桌子和背景
Picture 3 01A 分镜构图图 机位、景别、人物在画面中的位置和比例

三张图片各有分工：角色图提供“谁”，场景图提供“在哪”，构图图提供“从哪里看、主体放在哪里”。

项目里把第三张设为构图弱参考：主要借用镜头角度、裁切和位置，不要求照搬图里的每个细节。人物和场景的专用资产负责确定外观；动作、表情和物体状态还要看文字要求。

你自己练习时，也可以先准备一张人物图、一张场景图和一张构图图。素材和参考方式需要与所选工作流、模型的输入能力匹配；上传图片并不代表模型一定会完整遵循它。

三、把需求写成提示词

这个镜头采用的是 Pika H3 Flex 的参考素材生成方式。与上一篇的简单示例一样，这里要让模型知道每张图片是什么、如何使用；这次会进一步加入构图参考和对白。

项目中的提示词分为六部分：

部分 作用
subject_definitions 定义角色、场景和参考图的含义
summary 概括要生成什么画面
retention_analysis 说明各参考素材需要保留或借鉴哪些内容
detailed_description 描述构图、动作、运镜和对白
overall_soundscape 描述环境声和物理声音
non_diegetic_music 描述观众能听到的背景配乐；没有则写 N/A

例如，项目把主播定义为 <Subject 1>，其外观参考 <Picture 1>；把演播室定义为 <Subject 2>，其环境参考 <Picture 2>；<Picture 3> 则用作构图参考。对白放在镜头描述中，用说话人编号和 <d> 标记：

这是项目中的局部示例，实际提示词还描述了主播的声音、动作、镜头、参考关系和环境声，不能只复制这一行就期待得到完整镜头。环境声设为安静的演播室底噪，背景配乐暂写 N/A，留待剪辑时处理。

写好提示词后，要再次核对：Picture 1 是不是角色、Picture 2 是不是场景、对白有没有写对。文字里的编号必须与工作流里实际输入的图片顺序一致。

四、在 ComfyUI 中组织这个镜头

上一篇介绍了安装工具和准备模型。本项目的 01A 同样使用参考素材工作流，需要 MiniMax H3 的 Ref2VA 基础模型和匹配的 Pika H3 Flex Ref2VA 适配文件；FL2VA 文件不能直接当成 Ref2VA 文件。

工作流可以理解为下面这条链路：

项目中这个单镜画布大致做了以下事情：

  1. 加载 Ref2VA 基础模型、文本编码器、视频和音频组件，以及 Pika 的 Ref2VA 适配文件。
  2. 通过图片加载节点按顺序读取主播图、演播室图和 01A 构图图。
  3. 在参考视频节点中，把图片连接到对应的参考输入，并输入这个镜头的提示词。
  4. 设置横屏画幅、分辨率和生成时长。
  5. 由保存视频节点把生成结果写入输出目录。

如果自己搭建，建议先使用支持 Pika H3 Flex 参考素材生成的模板，并按照模板说明准备对应模型。画面里出现了图片节点，并不等于图片已经传给了模型；要检查节点连接、图片顺序和实际输入。

项目同时还准备过调用 Token01 的 API 工作流。它通过远程服务生成，与这里讨论的本地模型工作流是两条不同路径，不能把 API 测试结果直接当成本地模型的验证结果。

五、这个镜头设置了多少时长和画幅？

以项目中现有的 01A 单镜画布为例：

  • 画幅：16:9 横屏。
  • 单镜工作流分辨率设置：0.4 百万像素；具体宽高由工作流中的分辨率节点计算。
  • 时长输入：5 秒。
  • 参考图：主播、演播室、构图图，按上文的 1、2、3 顺序输入。
  • 保存前缀：video/mhr-all/mhr-01A，实际输出目录取决于 ComfyUI 的配置。

项目工作流使用 24 帧/秒，并将请求时长对齐到模型支持的帧数：5 秒请求在当前表达式下对应 124 帧，约 5.17 秒。因此，请求 5 秒不一定得到恰好 5 秒的文件；需要精确时长时，还要检查实际输出并在剪辑中处理。

项目也有多镜整合画布，但第一次运行建议先验证一个镜头：确认模型和节点正常、参考图确实生效，再考虑扩展到其他镜头。

六、生成之后检查什么？

本地工作流运行完成，不等于镜头已经可以使用。拿到结果后，可以按这张清单检查：

  1. 人物：是否只有一位主播？脸、眼镜和服装是否符合参考图？
  2. 场景和构图：演播室是否合理？脸、双手和桌面是否都在画面里？
  3. 动作和镜头：主播是否保持正对镜头？固定机位有没有意外移动？
  4. 声音：中文对白是否完整、清楚，音色是否接近要求？有没有额外说话声？
  5. 时长：实际文件多长？对白有没有被截断？是否需要裁切？

如果发现问题，先确认素材和连接是否正确，再针对最明显的问题调整提示词或参考图。保存每次尝试的参数和结果，方便比较。

上面的清单是验收方法，不是对该版本生成结果的宣称。项目文件记录了静态核对结果，但该本地工作流版本仍需实际生成样片，才能判断参考图、声音和动作是否达到要求。

七、从一个镜头到更多镜头

当一个镜头跑通后，可以沿用同样的方法准备下一镜：换成对应角色和场景，更新参考图顺序、提示词、时长与输出名称，再单独验收。项目中的整合画布能够组织多个生成任务，但不会自动把所有结果剪成成片。

先把一个镜头的输入、生成和检查走通，再逐步增加数量，遇到问题时也更容易知道是素材、提示词、工作流还是模型设置需要调整。

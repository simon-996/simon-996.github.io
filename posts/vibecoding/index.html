Vibe Coding 2026指南

Vibe Coding

更新于 2026-10-12：补充了编程 Agent 和桌面工作台。工具更新很快，下面的介绍以这个日期核实的官方信息为准，具体功能和使用额度请看各自官网。

Vibe Coding 是什么 🤔

Vibe Coding 直接翻译过来叫氛围编程，什么是氛围编程？放着 BGM 写代码？No No No

Vibe Coding 是一种由人工智能驱动的编程方式。简单来说，Vibe Coding 的核心是用自然语言描述你想要的“感觉”或意图，让 AI 负责生成、调试和优化代码，而开发者则更像一个“指挥官”，更关注最终效果，而不是逐行手写代码。码农 → 指挥官

这里顺便分清两个东西：Vibe Coding 是你怎么写项目，Agent 是帮你干活的工具。普通 AI 对话主要给你建议或代码，编程 Agent 还可以在你授权的范围内查看项目、修改文件、执行命令，把事情往前推进。

AI 辅助编程的范围更大，你也可以让 AI 写代码，自己认真审查每一次修改。用了 Agent，不代表你就得闭着眼睛 Accept All。

传统的开发过程：

  1. 写代码

  2. 出 Bug

  3. 挠头找 Bug

  4. 找不到

  5. 网上搜索求助，开十几个标签

  6. 尝试复制粘贴 StackOverflow、CSDN 的代码，结果报错更多了。

    ……

AI 对话开发过程：

  1. 打开 ChatGPT、DeepSeek、豆包

  2. 提出问题

  3. 复制代码到自己的代码里

  4. 报错

  5. 复制报错信息到 AI

  6. 粘贴回去，继续报错

    ……

Vibe Coding 开发过程：

  1. 告诉 AI 需求，顺便说清楚什么样算做完
  2. AI 查看项目，给出方案
  3. AI 写代码、运行测试、修复问题
  4. 你检查效果，不满意就继续调整
  5. 满意了，再收下这次的代码

指挥官也得验收，不能士兵说打赢了你就直接开香槟。

特点

  • 自然语言驱动：用“人话”描述需求，哪怕刚开始不会写代码，也能尝试做出简单工具或原型。至于能不能长期维护，那是下一关。
  • 意图大于实现：关注点从“怎么写代码”转移到“想要什么功能/体验”。
  • 高度信任 AI：有些开发者不审查 AI 生成的每一行代码，而是直接“Accept All”（全部接受），只看最终运行结果。Accept All 很爽，出了问题也得有人接得住。
  • 快速原型开发：在需求清楚、范围不大的时候，能缩短从想法到原型的过程，非常适合快速验证创意。

注意

Vibe Coding 不是说让 AI 替你思考，就什么都不做了。

AI 很智能，但 AI 始终是 AI，只是工具，不能代替我们思考。

  • 我们需要做的事情：这个项目有哪些功能？怎么设计？怎么架构？什么样算做完？最后检查它交出来的东西。
  • AI 可以做的事情：帮你讨论方案，根据你说的功能、结构写代码，运行测试、修复问题，指哪儿打哪儿。

比如你想给博客加个搜索框，就别只说“做一个好看的搜索”。可以告诉它：支持搜标题和正文，手机上也能用，搜不到时给出提示，保留原来的主题样式。需求说清楚，验收时你也知道该检查什么。

AI 很智能、很强大，但强大的士兵也需要强大的指挥官才能发挥出作用。

优势与风险

优势

  • 效率提升：重复性工作、简单脚本或快速搭建原型时，可以省下不少手写代码的时间。复杂项目能省多少，还得看需求、上下文和验收成本。
  • 门槛降低：让不懂编程的人也能尝试将想法变为现实，但从“能跑”到“好用、可靠”，还需要继续学习。
  • 激发创意：开发者可以专注于高层设计和用户体验，而不被繁琐的语法打断思路。

风险与局限

  • 代码质量隐患：AI 生成的代码可能存在安全漏洞、性能问题或不符合最佳实践，盲目接受会积累“技术债”。
  • 调试困难：当项目变得复杂时，如果不理解底层代码逻辑，一旦出现问题将难以排查和修复。
  • 关键系统要提高要求：涉及重要数据、安全和长期维护的项目，不能只凭“看起来能跑”就上线。AI 可以参与开发，但代码审查、测试和人工验收都得跟上。
  • 执行权限也要管：Agent 能执行命令、改文件，做错了也可能真改坏东西。给它合适的权限，重要修改先有备份或 Git 记录，指挥官得留条退路。

怎么 Vibe Coding

工欲善其事必先利其器，下面按主要使用入口，把工具分成三类，你可以根据场景选择你的“武器”。这是一份入门清单，工具当然远不止这些。

同一个产品可能有 IDE、终端、桌面和云端等多个入口，下面按这一节主要介绍的用法来放，别把分类当成它的能力上限。

1. AI 原生编辑器（IDE）

适合习惯一边看代码、一边调试的开发者。它们不仅仅是编辑器，更是你的结对编程伙伴。

Cursor

  • 定位：把 AI 编程能力融入编辑器的开发工具。
  • 杀手锏：Agent 可以搜索代码、修改多个文件、执行终端命令，帮助你完成实现和验证。读项目、改代码、跑检查，可以接着干。
  • 适合：日常项目开发、修 Bug、代码重构，尤其是想在编辑器里随时检查修改的开发者。

Trae

  • 定位：字节跳动推出的 AI 开发工具，提供 IDE 和 SOLO 等开发入口。
  • 杀手锏：Builder / SOLO 能把需求、代码、终端和预览串起来，帮你搭模块、做原型，再根据效果继续调整。
  • 适合：喜欢在可视化界面里完成开发、希望从想法快速做出项目的开发者。

2. 终端命令行工具（CLI）

运行在终端里，适合喜欢键盘操作、需要处理系统文件或自动化任务的“硬核”指挥官。

Claude Code

  • 定位：Anthropic 出品的编程 Agent，这里主要说它的终端用法，也有 IDE、桌面和网页入口。
  • 杀手锏：读取代码库、直接修改文件、执行命令。你可以让它“帮我重构这个模块，保留现有功能，运行测试并修复报错”，它会围绕这个任务连续执行。
  • 适合：项目开发、后端任务、运维脚本、代码重构。

Codex CLI

  • 定位：OpenAI 的编程 Agent 在终端里的入口，Codex 也有桌面应用和 IDE 扩展。
  • 杀手锏：结合项目上下文、文件操作和命令执行，推进代码修改和验证。把任务交给它，再检查它改了什么、验证了什么。
  • 适合：在现有代码库里加功能、修 Bug、审查代码，以及喜欢终端工作流的开发者。

Gemini CLI

  • 定位：Google 推出的开源终端 AI Agent。
  • 杀手锏：可以在终端理解和修改代码、执行命令，还能通过 MCP、扩展和 Skills 接入其他能力。终端里的兵种又多了一位。
  • 适合：项目探索、脚本开发、代码修改，以及想用 Gemini 处理终端任务的开发者。

CodeBuddy Code

  • 定位：腾讯 CodeBuddy 的命令行工具，和 CodeBuddy IDE 属于同一个工具体系。
  • 杀手锏：用自然语言在项目目录里推进开发任务，也可以和编辑器集成，结合 IDE 的文件、差异和诊断信息一起工作。
  • 适合：习惯终端、希望把 AI 编程接入现有编辑器或开发流程的开发者。

3. 桌面 Agent / 工作台

前面两类主要围着代码转，桌面端则把任务、文件和结果放进一个可视化工作台。有些专注开发，有些开始往整个工作流程里走了。写代码、整理文件、分析数据、做文档，都可以交给它试试。指挥官手下的兵种越来越齐全了。

ChatGPT 桌面端

  • 定位：OpenAI 的桌面工作入口，可以使用 Chat、Work 和 Codex。Chat 用来问问题、讨论想法，Work 更侧重交付工作成果，Codex 则把代码、Git 和命令执行等开发细节摆到你面前。
  • 杀手锏：Work 可以拆解任务、调用工具，完成研究、文档、表格和演示文稿；在已开放并授权的桌面环境里，也能使用本地文件、应用和浏览器。需要改项目、跑测试、看代码差异时，可以使用同一桌面端里的 Codex 入口。
  • 适合：想在可视化界面里管理任务、查看交付文件，同时兼顾编程和日常工作的用户。具体入口和能力取决于账号、套餐、平台及开放情况。

这里说的是桌面端里的 Agent 工作入口，前面的“打开 ChatGPT，复制粘贴代码”说的是普通对话用法。同一个名字，干活的方式也可以不同，别以为换了个聊天窗口就自动配齐了工具。

Claude Code 桌面版

  • 定位：Claude 桌面应用里的 Code 标签，也就是 Claude Code 的可视化入口。前面介绍的是它在终端里怎么用，这里说的是坐在桌面工作台里怎么指挥。
  • 杀手锏：读取项目、修改代码、执行命令，还可以在界面里查看代码差异、运行多个独立会话、使用集成终端和应用预览。士兵干了什么，指挥官能直接检查。
  • 适合：希望使用 Claude Code 开发项目，又喜欢通过图形界面管理任务、审查修改和查看结果的开发者。

Claude 桌面端还有 Chat 和 Cowork：Chat 用来对话，Cowork 面向更长的 Agent 工作任务，Code 面向软件开发。Claude Code 也不只住在终端里，换个入口，照样可以带兵干活。

DeepSeek Harness

  • 定位：DeepSeek 官方推出的开源 Agent 工具，目前处于公开预览阶段，可以使用桌面应用，也可以从源码启动 Web 界面。
  • 杀手锏：不只是对话，可以探索代码库、修改代码、运行测试，也能处理文档、数据和研究任务。采用“Everything is a plugin”的思路，通过插件扩展工具和工作流程。
  • 适合：想尝试 DeepSeek 官方 Agent、结合编程和文件处理，或者自己扩展 Agent 能力的开发者。

这里说的是 DeepSeek Harness，和 DeepSeek 聊天网页、底层模型、API 不是同一个东西。模型像士兵的脑子，Harness 还把工具和执行流程配齐了，才方便它动手干活。

WorkBuddy

  • 定位：腾讯推出的全场景 AI 办公工作台，覆盖办公、代码开发和设计创意。
  • 杀手锏：根据自然语言拆解任务、调用工具、操作授权的本地文件，交付文档、表格、PPT 等结果，也可以通过 Skills 和 MCP 扩展能力。
  • 适合：希望把资料整理、数据分析、文档制作和开发周边工作一起交给 Agent 的用户。

名字挺像，但 CodeBuddy 主要围绕编程，WorkBuddy 更偏整个工作流程。你要修项目里的 Bug，可以先看编程工具；你要整理一堆资料再做份汇报，工作台就更对口。选武器得看这次打什么仗。

补充

Vibe Coding 最开心的部分其实就是抽代码如同在抽卡。不同模型就像不同卡池，有的便宜，有的贵，但贵的卡池也不保证你每次都能单抽出奇迹，兜了一圈照样可能吃大保底。

你想一下，假如有一段很长的代码（你自己已经大概知道要怎么写了），但是你自己懒得写，那就可以用 Vibe Coding 抽卡，如果抽出来的代码完美符合你的要求，那就会很爽，如果不符合你的要求，那就很不爽。

如果一次就能成功生成，那就相当于单抽出奇迹，会非常爽。

如果第一次没生成成功，你也不需要气馁，你可以补全信息（继续氪金）继续抽。需求说清楚、任务拆小一点，再把不符合预期的地方告诉它，通常比原封不动再抽一次更有用。当然，代码抽出来了也得验收，能跑不等于没有 Bug。

不过也别每次都只发一句“还是不对”。需求没说清楚，验收标准也没有，你换个卡池照样可能吃大保底。

为什么我强调个人的古法编程能力仍然重要呢，就很像 100 抽大保底而你已经抽了 98、99 抽了，如果这次再充一个 648 来个十连就显得很蠢，明明你再做点日常就可以把最后两抽补齐的，就像 Vibe Coding 最后一点点小问题自己上手改几分钟就搞定了，实在没必要叽里呱啦又说一通需求等 Agent 又在那边 thinking 半天，费钱费时费力。
